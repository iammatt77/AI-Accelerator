## Séma-döntés (A7.1) — indoklás

**Egységesített cél-modell + KÉT valódi owner-FK oszlop** (nem szöveges polimorf owner):

```
component_links (
  id, solution_component_id NULL FK→solution_components ON DELETE CASCADE,
      build_component_id    NULL FK→build_components   ON DELETE CASCADE,
  target_type CHECK in (requirement|story|tobe_node|pain_point),
  target_id text,                 -- soft-ref (lásd lent)
  process_map_id NULL FK, state entity_state, created_at,
  CHECK num_nonnulls(owner-pár) = 1,
  CHECK solution-owner → target_type = 'tobe_node',
  UNIQUE (coalesce(owner), target_type, target_id)
)
```

- **(a) Mindkét szemantika megkülönböztethetően:** a P2 dokkolás solution-ownerrel (cél kényszerítetten `tobe_node` — CHECK), a P3 megvalósítás-kötés build-ownerrel (4 cél-típus). Nem két külön „kind" oszlop kell hozzá — a struktúra hordozza.
- **(b) A kötés-fajta a sorból visszaállítható:** melyik owner-oszlop nem NULL. Ez erősebb, mint egy szöveges `owner_type`: a DB-kényszer garantálja, hogy pontosan egy, és típushelyes.
- **(c) Hivatkozás-integritás:** az ownerekre és a `process_map_id`-re **valódi FK** cascade-del — a komponens-törlés viselkedése (kötések automatikus takarítása) változatlan, és a dokkolás oda-vissza forgatókönyv ezt igazolta. A **cél soft-ref marad** (`target_type` + `target_id` szövegként), dokumentált indokkal: a négy cél-típus három uuid-táblát ÉS a `process_maps` jsonb-n **belüli** stabil node-id-t fedi — polimorf célra Postgres-FK nem tehető; ez azonos a kivezetett `impl_links` megoldásával, tehát integritás-szintet nem vesztettünk, miközben a dokkolás-oldal az eddigi PK-nál erősebb unique-ot kapott.
- **Elvetett alternatíva:** szöveges `owner_type + owner_id` polimorf owner — egyszerűbb séma, de az ownerre sem lehetne FK (a cascade-viselkedés és az árvasor-védelem elveszne); a két-oszlopos megoldás ára (egy CHECK + coalesce-os unique index) kisebb, mint a haszna.
- Az egységes `state` a dokkolás-sorokon `manual` (a dokkolás emberi felvétel; a dokk-olvasó nem szűr state-re — viselkedés változatlan), a megvalósítás-kötéseken a meglévő E1-lánc (`ai_suggested` → ✓ `confirmed` / × törlés).
